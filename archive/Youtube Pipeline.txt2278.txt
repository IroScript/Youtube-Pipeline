  গণ্য করবে না।

  2. আবার কোনো requirement-এ REST API, HTTP endpoint, API-accessible workflow, external client integration বা backend API explicitly required
  থাকলে, CLI/script/internal service ready থাকা REST API requirement পূরণ করেছে বলে গণ্য করবে না।

  3. প্রতিটি pipeline stage-এর ক্ষেত্রে এই ৩টি বিষয় আলাদাভাবে যাচাই করবে:

     * Requirement কী চেয়েছে?
     * বর্তমান implementation আসলে কী দিয়েছে?
     * Requirement পূরণের জন্য REST API সত্যিই প্রয়োজনীয় কি না?

  4. “REST API নেই” এবং “functional pipeline নেই”—এই দুইটিকে এক জিনিস হিসেবে ধরবে না।

  5. CLI/worker/internal Python service দিয়ে কোনো stage সম্পূর্ণভাবে কাজ করতে পারলে এবং requirement-এ API বাধ্যতামূলক না থাকলে সেটিকে functional
  হিসেবে মূল্যায়ন করবে।

  6. বিপরীতে requirement যদি API endpoint দাবি করে, তাহলে exact missing endpoint দেখাবে এবং সেটিকে implementation gap হিসেবে চিহ্নিত করবে।

  7. একই নিয়ম পুরো 97টি requirement-এর ক্ষেত্রে প্রয়োগ করবে। শুধু Element → 10 Ideas stage নয়।

  8. কোনো requirement-এর verdict দেওয়ার আগে immutable master requirement text-এর সঙ্গে সরাসরি মিলাবে। নিজের interpretation দিয়ে নতুন requirement
  তৈরি করবে না।

  9. বিশেষভাবে আলাদা করবে:

     * Functional capability exists
     * CLI-only capability
     * Internal service capability
     * REST API capability
     * Live external integration capability
     * End-to-end production capability

  10. কোনো একটি layer অনুপস্থিত থাকলে পুরো feature অনুপস্থিত বলে ঘোষণা করবে না, যদি requirement সেটি বাধ্যতামূলক না করে।

  11. আবার কোনো বাধ্যতামূলক layer অনুপস্থিত থাকলে “CLI ready”, “script ready”, “backend implemented” ইত্যাদি দিয়ে সেটিকে VERIFIED করবে না।

  12. প্রতিটি সন্দেহজনক verdict-এর জন্য exact requirement number, requirement wording, implementation evidence এবং কেন PASS/PARTIAL/FAIL—তা দেখাবে।

  13. REST API নিয়ে অনুমান করবে না। Requirement/architecture/code evidence ছাড়া “API required” বা “API not required”—কোনোটিই ধরে নেবে না।

  14. আগের রিপোর্টে যদি কোনো requirement শুধু REST API না থাকার কারণে PARTIALLY_VERIFIED করা হয়ে থাকে, requirement text পুনরায় যাচাই করে প্রয়োজন
  হলে verdict সংশোধন করবে।

  15. এই correction-এর পর পুরো 97-requirement ledger-এর consistency পুনরায় যাচাই করবে এবং কোথায় REST API-related false positive/false negative
  হয়েছে তা রিপোর্ট করবে।

  NO FALSE GREEN:
  Requirement-এ API explicitly required হলে API না থাকা অবস্থায় VERIFIED করা যাবে না।

  NO FALSE RED:
  Requirement-এ API explicitly required না হলে শুধু API endpoint না থাকার কারণে functional requirement-কে PARTIAL/FAIL করা যাবে না।

  ## ৪. মাস্টার অডিট প্রশ্নের সরাসরি উত্তর (Master Audit Question Answer)

  │ প্রশ্ন: "আমি যদি Python internal functions, CLI এবং direct database access একদম না ব্যবহার করে শুধুমাত্র documented REST API ব্যবহার করি, তাহলে কি সম্পূর্ণ YouTube
  │ Pipeline operate করতে পারি?"

  ### উত্তর: YES.

  এখন একজন এক্সটার্নাল ক্লায়েন্ট শুধুমাত্র REST API কল করে পুরো পাইপলাইন সম্পূর্ণভাবে পরিচালনা করতে পারবে:

  1. Category & Element: GET /ideas/categories ও GET /ideas/elements দিয়ে ক্যাটাগরি ও এলিমেন্ট তালিকা পাওয়া যাবে, প্রয়োজনে POST
  /ideas/categories/{id}/elements/generate দিয়ে নতুন এলিমেন্ট তৈরি করা যাবে।
  2. Ideas: POST /ideas/elements/{id}/generate দিয়ে স্বয়ংক্রিয় ১০টি আইডিয়া জেনারেট করা যাবে অথবা POST /ideas দিয়ে কাস্টম আইডিয়া যোগ করা যাবে।
  3. Prompt Escalation: POST /prompts/{idea_id}/escalate দিয়ে ১ থেকে ১০ লেভেলের ২০টি প্রম্পট স্বয়ংক্রিয়ভাবে তৈরি হবে এবং GET /prompts/{idea_id}/levels/10 দিয়ে সরাসরি লেভেল ১০
  প্রম্পট পাওয়া যাবে। JIT রেজোলিউশনের জন্য POST /prompts/next-production-ready বিদ্যমান।
  4. Anti-Duplication Audit: GET /uniqueness/audit, GET /uniqueness/novelty ও GET /uniqueness/ideas/{id}/variation দিয়ে ডুপ্লিকেশন ও ভ্যারিয়েশন যাচাই করা যাবে।
  5. SEO Harvesting & Generation: POST /seo/harvest/suggest ও POST /seo/harvest/competitors দিয়ে লাইভ ইউটিউব কি-ওয়ার্ড স্ক্র্যাপ করা যাবে এবং POST
  /seo/{idea_id}/generate দিয়ে এসইও তৈরি হবে।
  6. Video Render & Assembly: GET /videos/{idea_id}/render-payload দিয়ে ভিডিও অটোমেশনের সম্পূর্ণ পেলোড নেওয়া যাবে, POST /videos/{idea_id}/generate দিয়ে ভিডিও রেন্ডার করা যাবে
  এবং POST /videos/{idea_id}/assemble দিয়ে একাধিক শট স্টিচ করা যাবে।
  7. Audio / Voiceover TTS: GET /audio/{idea_id}/status এবং POST /audio/{idea_id}/generate দিয়ে স্পিচ সিন্থেসিস চালানো যাবে।
  8. Packaging: POST /packages/{idea_id}/bundle কল করলে সমস্ত আর্টিকেক্ট (ভিডিও, অডিও, এসইও JSON, প্রম্পট JSON) প্যাকেজড ডিরেক্টরিতে একত্রিত হবে।
  9. Publishing / YouTube Upload: GET /youtube/{idea_id}/payload দিয়ে মেটাডাটা প্রিভিউ করে POST /youtube/{idea_id}/upload দিয়ে ইউটিউব ডিসপ্যাচ করা যাবে।
  10. Reports & Exports: POST /exports/csv দিয়ে এক ক্লিকে সম্পূর্ণ পাইপলাইনের সমস্ত CSV রিফ্রেশ ও এক্সপোর্ট করা যাবে।
  11. One-Click Orchestrator: ক্লায়েন্ট চাইলে সরাসরি POST /pipeline/ideas/{idea_id}/run ট্রিগার করতে পারে যা 202 Accepted রিটার্ন করে এবং ব্যাকগ্রাউন্ডে পুরো সিকোয়েন্স চালায়, যার অগ্রগতি GET
  /pipeline/ideas/{idea_id}/progress দিয়ে স্টেপ-বাই-স্টেপ ট্র্যাক করা যায়।
